# Security Design

## 信頼境界

NPU Codexは、次の3者を分離します。

1. Codex CLIとその承認・サンドボックス
2. loopback HTTPブリッジ
3. 信頼できない生成器としてのローカルモデル

モデル出力は常に不正・誤り・プロンプトインジェクションを含み得るものとして扱います。

## 実装済み対策

### ネットワーク

- 既定で`127.0.0.1`のみへbind
- `security.loopback_only = true`時、loopback以外の設定を起動前に拒否
- Hostヘッダーがloopbackを示さない要求を拒否
- 任意のBearer認証
- CORSを有効化しない
- APIドキュメント公開を無効化

### リクエスト

- `Content-Length`の事前確認
- 圧縮本文そのものの上限
- gzip / zstdの展開を上限+1バイトで停止
- 展開後本文の上限
- 不明な`Content-Encoding`を拒否

### モデル出力

- JSON actionを1件だけ解析
- リクエストで提示されたツール名だけを許可
- function/custom種別を照合
- required、基本型、enum、追加プロパティ等を限定検証
- 不正actionの修正生成回数を制限
- 最終的に不正ならツールを呼ばない

### 秘密情報

- APIトークンは環境変数から取得
- 既定でアクセスログを無効化
- リクエスト本文をログへ出力しない
- `.env`、`auth.json`、`.codex-local`、モデル、キャッシュを`.gitignore`で除外
- 通常のCodex homeと専用`CODEX_HOME`を分離

## 残るリスク

### 同一ユーザー権限のローカルプロセス

loopback限定は、同一PC上の他プロセスを信頼することを意味しません。必要に応じてBearer認証とOSファイアウォール、アプリケーション制御を組み合わせてください。

### Codexが提供するツール権限

ブリッジがツール名を検証しても、そのツール自体が強い権限を持つ可能性があります。Codexの承認モード、書込み可能範囲、ネットワーク権限、作業ディレクトリを最小化してください。

### 小型モデルの誤判断

モデルは危険なコマンドや不正確なパッチを提案できます。自動承認を前提にせず、特に削除、資格情報、ネットワーク、依存更新、ビルドスクリプトを人が確認してください。

### Pythonプロセス

Python依存関係やモデル変換ツールはサプライチェーンの一部です。閉域持込み時は、wheelとモデルのハッシュ、署名、入手元、ライセンスを記録してください。

### 完全なJSON Schemaではない

検証器は小型・保守的なサブセットです。`$ref`、複雑な条件式、すべての数値・文字列制約を網羅しません。最終的な入力検証はCodex側ツール実装でも行われる必要があります。

## 推奨運用

- 専用の非管理者ユーザーで評価
- 評価用リポジトリのコピーで開始
- Codexの書込み範囲を対象リポジトリへ限定
- 外向き通信はOS側で明示的に制御
- `allow_cpu_fallback = false`を維持し、NPU利用を診断で確認
- モデルとwheelのSHA-256を台帳化
- 生成パッチ、実行コマンド、エラーを監査可能な形で保存
- 実運用前に脅威モデルとペネトレーション試験を実施
